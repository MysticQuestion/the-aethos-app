

Aethos, at its core, is not a horoscope generator. It’s an astrology-native intelligence platform that treats astrology as structured data + time-series events + calibrated self-tracking, then converts that into timing forecasts and high-quality interpretive synthesis with auditable logic. 


---

1) Aethos in one sentence

Aethos is a “calculation → interpretation → timing intelligence” stack behind a single product API, where deterministic chart math produces event windows, LLMs synthesize meaning under strict governance, and a longitudinal feedback layer learns what timing patterns actually correlate with the user’s lived data. 


---

2) The three coupled engines (the canonical architecture)

Your platform is best understood as three coupled engines—each with distinct responsibilities, data contracts, and cost profiles. 

A) Calculation Engine (Deterministic “numerical truth”)

Purpose: Produce precise, reproducible astronomical/astrological primitives.

Outputs (examples):

Planetary longitudes/latitudes, houses, aspects

Retrograde/station detection (via speed vectors)

Ingresses, eclipses windows, transit-to-natal “hits” with exact peak times

(Optional expansions) progressions, solar returns 


Core software / libraries:

Swiss Ephemeris as the high-precision computation layer (the “metaphysics engine”): positions + velocities, with strong accuracy claims tied to JPL DE431 compression and agreement. 

Aethos’ dev doctrine emphasizes correct handling of the ephemeris tuple (“Big Six”: lon/lat/dist + three speed terms) specifically because velocity is needed for retrograde/station logic and cycle kernels. 


Correctness “gotchas” Aethos treats as first-class:

Time zone and geocoding discipline: store UTC + original local + IANA TZ + lat/long; version computations for reproducibility. 

Licensing discipline: Swiss Ephemeris is dual-licensed; proprietary SaaS posture typically implies a professional license (and the license text explicitly contemplates server use). 



---

B) Interpretation Engine (Governed LLM synthesis, not “LLM math”)

Purpose: Convert structured chart/time data into coherent, psychologically literate output—while keeping generation a governed cost center (caching, batching, versioning).

Key design principle: LLMs should not “calculate”—they should interpret validated JSON returned by deterministic engines (e.g., Swiss Ephemeris; MCP-style compute services). 

Aethos modes:

Story Mode: high-value narrative synthesis from normalized “theme scores” and event windows. 

Lab Mode: transparency-forward output exposing kernels and source contributions (traceability as a product feature, not an afterthought). 


Interpretation governance:

Prompt/version control for reproducibility

Structured outputs (JSON schemas) for composability

Regression testing across a fixed suite of charts (interpretation consistency becomes the product) 



---

C) Timing Intelligence Engine (the moat)

Purpose: Move beyond “upcoming transits” into forecasting under uncertainty—calibrated against the user’s longitudinal signals.

Aethos defines timing intelligence as:

1. deterministic generation of precise event windows (start/peak/end), and


2. a statistical layer estimating how those windows correlate with the user’s self-reported (and optionally behaviorally inferred) outcomes—yielding expected impact distributions + confidence, not prophecy. 



This is explicitly positioned as the most defensible moat, because chart math and LLM prose are commoditizing; a closed-loop timing system built on consented longitudinal measurement is harder to copy quickly.

4) The multi-agent “Agents’ Room” narrative service (Aethos’ long-form engine)

Aethos includes a production blueprint for long-form synthesis that avoids the classic failure mode of single-shot generation (“coherence gap,” drift, tone discordance). The system decomposes writing into specialized planning + writing agents coordinated via an orchestrator and a shared scratchpad. 

Core components

Orchestrator: the state machine / conductor deciding which agent runs next based on scratchpad state. 

Scratchpad: shared memory—prevents contradictions and supports human-in-the-loop editing midstream. 

Planning agents (“Architects”): CONFLICT, CHARACTER, SETTING, PLOT 

Writing agents (“Scribes”): EXPOSITION, RISING ACTION, CLIMAX, FALLING ACTION, RESOLUTION 


Why this exists inside Aethos

Because one of Aethos’ differentiators is that it can deliver professional-grade, long-form outputs (reports, dossiers, “year-ahead” narratives) without collapsing into generic filler—by turning generation into a governed pipeline, not a single prompt.

5) Psychological instrumentation layer (measurement, not vibes)

Aethos’ “psychological rigor” is implemented operationally via a structured journaling / EMA layer—short daily measures that enable calibration of timing forecasts. 

Core instruments (product-level)

EMA-style check-ins (1–2 minutes/day): mood, stress, focus, connection, sleep quality, decision confidence—plus optional richer check-ins during predicted windows. 

Optional psychometrics framing (Big Five as a stable trait backbone) as a more defensible personality structure than trendier typologies. 


This layer is what enables the Timing Intelligence Engine to say, credibly:
“Here’s the event window; here’s how your own data has historically responded to similar windows; here’s the confidence range.”
