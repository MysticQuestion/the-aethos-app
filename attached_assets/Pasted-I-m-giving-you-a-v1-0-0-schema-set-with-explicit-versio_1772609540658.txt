- Detect any change in: 
 
  - planet longitudes (beyond tolerance)
 
  - house assignments
 
  - aspect detection
 
  - retrograde flags
 
  - derived sect/dignities
 
  - event windows (peak times drift)
 

 
 

 
## 10.2 Create **20 Golden Charts** (minimum)
 
Split them deliberately:
 
### A) “Standard” (8 charts)
 
 
- spread across decades (1950s–2020s)
 
- varied latitudes (equator, mid-latitude, high-latitude)
 
- varied timezones and DST boundaries
 

 
### B) “Edge cases” (12 charts)
 
 
1. Birth near DST transition (spring forward)
 
2. Birth near DST transition (fall back)
 
3. High latitude: near Arctic Circle (houses tricky in quadrant systems)
 
4. Moon at late degree (29°xx) sign boundary
 
5. Mercury station day (speed near 0)
 
6. Venus retrograde period
 
7. Mars station day
 
8. Leap day birth (Feb 29)
 
9. Time unknown (null time; must produce reliability flags)
 
10. Time approximate ±60 minutes (must produce reliability envelope)
 
11. Birth at 00:00:00 boundary
 
12. Birth at 23:59:59 boundary
 

 
## 10.3 Assertions (what you compare)
 
For each golden chart, store expected outputs:
 
### Planet tolerances
 
 
- longitude difference ≤ **0.0003°** (≈ 1 arcsecond) if using same ephemeris build
 
- speed difference ≤ small epsilon
 

 
### Derived features exact match
 
 
- sign
 
- house
 
- retrograde boolean
 
- sect
 
- dignity status (given your dignity ruleset)
 

 
### Aspect graph stable match
 
 
- same set of aspect edges, same aspect types
 
- orb difference within tolerance
 

 
### Event windows stable match
 
 
- peak time drift ≤ **5 minutes** for exact aspects/stations (tight)
 
- start/end windows drift consistent with orb policy
 

 
## 10.4 Snapshot testing format
 
Store each golden output as:
 
 
- canonical JSON
 
- plus a reduced “summary digest”: 
 
  - list of body longitudes rounded to 0.001°
 
  - aspect list
 
  - derived flags
 
  - hash
 

 
 

 
That makes diffs readable.

## A) Option A modeling (correct handling of “local time”)
 
**Rule:** treat *local* birth datetime as **naive components** + **IANA timezone**, and treat **UTC** as the only absolute timestamp.
 
So the Birth Record stores:
 
 
- `birth_local_date` (`YYYY-MM-DD`)
 
- `birth_local_time` (`HH:MM[:SS]`)
 
- `birth_timezone` (IANA, e.g. `America/Los_Angeles`)
 
- `birth_utc_datetime` (`RFC3339 Z`)
 
- `julian_day` (float)
 

 
This avoids the category error of treating “local time” as an absolute instant.

## 3.4 `tools/validation/golden_runner.py`
 
This runs schema validation + optional numeric tolerances (placeholders included).
